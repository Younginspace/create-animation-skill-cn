# 中文短动画创意方向

用于纯文字表情、无图卡片，以及用户明确要求“更好看、更有氛围、更像设计作品”的任务。先完成创意计划，再写或修改 composition。

## 先自动路由，再生成画面

脚手架必须用 `cn-context-router-v2` 自动完成一次可审计的 Creative 判断，而不是只生成通用模板：

1. 从功能、文案、风格、使用场景、素材状态和受众线索提取信号。
2. 明确受众、语气、构图模式、视觉隐喻、装饰预算和文字角色，再选择色板、字体职责与动作节拍。
3. 同属“生日”也要继续分流：给成年父母的生日祝福默认走温暖、克制、有仪式感的中式当代美学；儿童或热闹语境才使用高饱和纸屑、气球或蛋糕。
4. 工作回复、聊天状态、聚餐邀请、考试鼓励和父母生日必须形成不同画面骨架，而不只是换色。
5. 生成的根节点写入 `data-creative-engine="cn-context-router-v2"`；`creative-plan.json` 同步记录触发信号和决策，供验证与回放站展示。

## 先解释，再装饰

1. 用一句话写清“这条动画要让观众先感到什么、再读到什么”。
2. 把原文分成语义角色：提示、主句、补充、署名。只重排用户原话，不新增姓名、日期、地点、关系或承诺。
3. 选择一个主视觉隐喻，例如状态确认、前进、团聚、生日仪式或倒计时。不要把“加图形”当作概念。
4. 删除与语义、层级、可读性都无关的元素。

## 按视频画面构图

- 不使用网页默认的“背景 + 中央圆角卡片 + 图标 + 文字”。
- 建立背景、中景、前景职责。背景负责气氛，中景负责结构或语义线索，前景负责文字和必要强调。
- 纯文字作品通常需要两个视觉支点：主标题是第一焦点，提示语、日期、状态符号或结构图形是第二焦点。
- 主标题可占画面宽度约 60%—88%；聊天缩略图中的核心文字建议不小于 90px。
- 使用非对称、贴边、上下分区、斜向动势或纵向排版建立张力。居中布局只有在仪式感或极短反应词确实需要时采用。
- 字距、行距和留白必须服务阅读顺序；禁止让所有文字同字号、同字重、同时间出现。

## 配色与中文排版

- 先确定语气，再确定色板。每个作品以一个底色、一个文字色和一个强调色为主；第二强调色只承担状态或层级。
- 工作群回复可使用深墨、琥珀橙、状态绿；家庭祝福可使用米白、朱砂、暖粉或墨色；考试加油可使用黑蓝、荧光绿或高对比橙。
- 不因为“中文”就默认红金、印章、祥云或国潮纹样。只有节日、传统仪式或用户语义明确支持时才使用。
- 使用本机或随 Skill 合法打包的中文字体。不得依赖 Google Fonts 或渲染时联网取字体。
- 建立字重反差：提示语紧凑，主标题极重，副标题常规。避免整张画面只有一种中等字重。

## 动效编排

- 使用 `build → breathe → resolve`：先建立次焦点，再让主信息以更强动作进入；稳定阅读时只保留低幅环境运动；循环时共同回到首帧，非循环时稳定结束。
- 动态表情的首帧例外于“信息后入场”：`t=0` 必须已经保留核心文字和主体，`build` 表示语气强化而不是从空白开始。卡片和照片故事仍可按叙事需要逐层建立。
- 不同角色使用不同方向、速度或缓动。提示语可快速滑入，主标题可回弹砸入，强调线可横向扫入，背景只缓慢呼吸。
- 入场通常比退场更长；第一秒内必须形成可读信息。
- 动效必须可寻帧：同一时间值始终产生同一画面，不使用墙上时钟、随机数或独立 `requestAnimationFrame` 循环。

## 创意验收

- 缩到聊天气泡大小，第一眼能否找到主句？
- 去掉颜色后，字号、位置和节奏是否仍有明确主次？
- 是否至少有一个与语义有关的第二支点，而不是装饰噪声？
- 背景、中景、前景是否各有职责？
- 主标题、提示语、结构元素是否采用不同但协调的动作？
- 画面是否在表达用户原话，而不是展示模板能力？
- 自动路由的受众、语气、构图和隐喻是否能从画面中被看见，而不是只存在于 JSON？
